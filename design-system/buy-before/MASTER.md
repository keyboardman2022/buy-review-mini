# 买前问问小程序设计系统

本文件结合 ui-ux-pro-max 的移动端检索结果与产品语义制定。检索返回的营销落地页结构不适合应用内工作流，因此未采用其 Hero/CTA 页面模式。

## 设计方向

- 产品气质：朋友间坦率、温和、有边界的消费讨论。界面克制，不做购物平台式促销刺激。
- 主色 `#0F5C56`，主色文字 `#FFFFFF`；强调色 `#D95F45`，强调色文字 `#FFFFFF`。
- 背景 `#F7F2E9`，卡片 `#FFFDF8`，正文 `#173F3E`，次要文字 `#5F6964`，边框 `#D8D6CD`，错误 `#9B3528`。
- 使用微信系统字体，不加载网络字体。价格使用等宽数字特性可用时启用。
- 4/8dp 间距节奏；页面边距 16px，卡片间距 12px，卡片内边距 16px，主区块间距 24px。
- 所有按钮和可点击行至少 48px 高，相邻触点至少 8px 间距；按下态只改变透明度/颜色，不改变布局。
- 四个顶层入口固定为购物圈、购物车、审批、我的。深层页面保留系统返回，不用弹窗代替主流程。

## 页面规则

- 购物圈第一屏直接显示好友商品卡片。卡片顺序：作者与时间、商品与价格、理由、图片、赞/踩/评论。
- 我的购物车突出唯一主操作“添加商品”；删除属于危险操作，必须二次确认。
- 发起审批用三段清晰步骤：商品、好友、规则。每项均显示选中态文字与图形，不只依赖颜色。
- 投票页先展示不可变商品快照和目前意见，再显示评论输入与接受/拒绝按钮。评论有可见标签和提示。
- 表单字段始终显示标签；金额调用数字键盘；错误紧邻相关区域，并给出恢复方式。
- 网络请求超过短暂时间显示稳定加载文案或骨架；提交期间按钮禁用并显示正在处理；成功后给出明确反馈。
- 图片固定比例并预留空间，列表图片延迟加载；最多三张，单张 3MB。
- 空状态包含原因和一个下一步动作。审批结果同时显示文字、状态色和票数，不能只靠颜色。
- 不使用 emoji 充当结构图标。原生小程序首版使用文字标签与简洁 CSS 图形，后续有正式品牌图标时统一替换。

## 可访问性与适配

- 正文按 16px 等效字号设计，行高至少 1.5；重要小字不低于 14px 等效。
- 控件使用 `aria-role`、`aria-label` 或可见文字；图片提供可理解的替代说明。
- 固定底部操作避开 `env(safe-area-inset-bottom)`，滚动区保留对应底部空间。
- 375px 小屏不得横向滚动；平板限制内容宽度并增大两侧留白；横屏保持单列主流程，不把表单挤成多列。
- 只保留 150–200ms 的按下反馈和必要状态过渡；不使用滚动视差、自动轮播或无法关闭的动效。
